# PromotedTools档案

## 一、这个类是干什么的

PromotedTools是延迟工具提升记录的状态载体。

DeerFlow的工具有延迟加载机制。
一部分工具初始不出现在模型请求里。
需要时才被提升进模型请求。
每次提升会改变工具目录。
PromotedTools记录的就是被提升的工具清单。

这个类解决的问题和工具目录漂移有关。

工具目录会变化。
目录变了之后。
之前提升的旧工具名可能指向完全不同的工具。
如果无脑保留旧名字。
一个持久化的裸名字可能在目录漂移后暴露另一个不同的工具。
这是安全隐患。
PromotedTools用catalog_hash来解决这个问题。
记录里带着提升时的目录哈希。
目录哈希变了。
提升记录整体作废。

这个类的定义。

```python
class PromotedTools(TypedDict):
    catalog_hash: str
    names: list[str]
```

两条字段。
catalog_hash是提升发生时的工具目录哈希。
names是被提升的工具名列表。

这个类在什么场景被使用。
ThreadState的promoted字段使用这个类型。
工具提升中间件写入提升记录。
检查点保存时随线程持久化。

## 二、类的成员（字段、方法，各自做什么）

### （一）字段

- catalog_hash：工具目录的哈希。类型是str。
这个哈希在提升发生时记录。
它是提升记录的失效锚点。
目录漂移后哈希不再匹配。
旧提升记录整体替换。

- names：被提升的工具名列表。类型是list[str]。
这些名字是延迟工具被提升后的名字。
模型请求里会看到这些工具。

### （二）方法

这个类没有任何方法。
它是纯数据结构。
提升的全部合并逻辑在模块级的merge_promoted函数里。

### （三）配套的reducer

promoted字段绑定merge_promoted这个reducer。
输入是已有提升记录和新提升记录。
输出是合并后的记录。

合并规则如下。

- 新值是None或空就保留已有值。节点没碰提升就不改变。
- 已有值是None或catalog_hash不一致就整体替换。只保留新记录的名字。丢弃陈旧名字。防止持久化的裸名字在目录漂移后暴露不同的工具。
- catalog_hash相同就取名字并集。去重并保留顺序。

## 三、它和谁协作

### （一）被组合

- ThreadState的promoted字段使用这个类。
字段定义是Annotated[PromotedTools | None， merge_promoted]。

### （二）协作的函数和模块

- merge_promoted函数。负责按目录哈希分组合并。
- 工具提升相关的中间件。负责写入提升记录。
- 工具目录系统。提供目录内容和哈希。
- 检查点持久化层。保存提升记录。

### （三）关联的机制

延迟工具机制的工作方式如下。
初始工具集不含延迟工具。
运行中按需把延迟工具提升进请求。
提升会更新工具目录。
目录更新产生新的catalog_hash。
PromotedTools记录哈希和名字。
保证提升状态和目录状态一致。

## 四、重要性评级（1-10分+理由）

评级是5分。

理由如下。

PromotedTools是一个两字段的纯数据结构。
体积很小。

但它的设计解决了一个真实的安全问题。
工具目录漂移后。
持久化的旧工具名可能解析到不同的工具。
这是工具注入类风险的变体。
catalog_hash机制让提升记录随目录漂移整体失效。
这个保证有实际的安全价值。

这个类还支撑了延迟工具功能的状态持久化。
没有它。
跨检查点的提升状态无从谈起。

但是要看到使用范围。
延迟工具机制是一个可选特性。
不是每次运行都会触发工具提升。
不使用延迟工具的系统不会触碰这个类。

如果删掉这个类。
promoted字段就失去类型。
延迟工具提升状态无法跨检查点保存。
每次检查点恢复后提升状态丢失。
功能退化但系统核心不受影响。

依赖它的地方是ThreadState和merge_promoted。
范围集中。

综合来看。
这是一个小而有安全价值的功能类型。
评级给5分。
