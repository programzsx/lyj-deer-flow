# deerflow.skills.review.digest-档案

## 一、这个模块是干什么的

这个文件是审查快照的规范包摘要。

它只有一个函数。

这个函数给一份包快照计算SHA-256摘要。

摘要是宿主机路径无关的。同样的包内容在任何主机上得到同样的摘要。

摘要的用途是标识包内容。审查报告里引用它。同一份包重新审查时可以对比摘要判断内容有没有变。

## 二、模块里的主要成员

### 1、compute_package_digest函数

这是唯一的函数。

它接收快照字典。

处理流程分几步。

第一步。遍历快照的文件列表。

第二步。对每个文件构建一条记录。记录由四段组成。用NUL字节连接。四段是kind文件类型、path规范化路径、size大小、content_digest内容哈希。

path用normalize_relative_path规范化。规范化会拒绝绝对路径和逃逸路径。

size取整。默认0。

content_digest取sha256字段。缺失时是空字符串。

第三步。全部记录排序。

第四步。逐条更新SHA256。每条记录前先更新记录的长度。8字节大端。

长度的作用是分隔记录。防止两条记录的字节流产生歧义。

第五步。返回sha256:加十六进制摘要。

记录排序让摘要和文件顺序无关。同一份包不管文件按什么顺序枚举，摘要相同。

## 三、它和谁协作

它依赖review包的models里的normalize_relative_path。

它被review的analyzer调用。analyzer把摘要放进facts的subject里。

它被review的renderer间接引用。报告里显示摘要。

它被contracts/skill_review的契约锚定。

它只用hashlib标准库。

## 四、重要性评级

评级是4分。

理由是这个文件是审查身份的锚点。

摘要让同一份包在不同主机、不同时间的审查结果可以对比。

排序加长度分隔的设计保证了摘要的确定性。

不评高分是因为它只有一个函数。逻辑量很小。不参与决策。
