# app.gateway.routers.trash-档案

源码路径是backend/app/gateway/routers/trash.py。

## 一、这个模块是干什么的

trash.py是回收站路由。

回收站是项目文档的可恢复删除区。

用户删掉的文档先进回收站。

回收站里的文档可以恢复或彻底清除。

这个模块有240行。

## 二、模块里的主要成员

路由前缀是/api/trash。

### 1、端点列表

- GET "/documents"列出回收站文档。
- POST "/documents/{document_id}/restore"恢复一个文档。
- POST "/documents/{document_id}/purge"彻底删除一个文档。
- POST "/purge"清空回收站。

### 2、保留清扫

list端点先触发保留清扫。

清扫按保留期删除过期文档。

清空回收站不过滤年龄。

清空删除调用者的全部回收站文档。

保留期清扫是清扫程序的职责。

### 3、失败封闭原则

缺失或外部的文档返回404。

恢复到归档或外部项目返回404。

永远不返回403。

403会泄露存在性。

memory后端部署返回503。

purge不带恢复语义。

彻底删除不可撤销。

## 三、它和谁协作

上游是前端回收站页面。

下游是回收站存储。

被删文档来自project_documents模块。

恢复把文档放回项目文档架。

清扫程序在app.py的lifespan里定时跑。

## 重要性评级

评级是5分。

理由如下。

回收站给文档删除加了后悔药。

恢复和清空是标准回收站语义。

失败封闭原则和project_documents一致。

但回收站是项目功能的辅助模块。

没有回收站，删除就是永久删除。

核心对话不依赖它。

所以评级是5分。
