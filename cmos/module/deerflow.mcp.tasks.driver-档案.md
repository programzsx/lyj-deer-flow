# deerflow.mcp.tasks.driver

## 一、这个模块是干什么的

这个模块定义MCP长任务的驱动层契约。

背景是这样的。

长时间运行的MCP工作需要一个独立的持久化任务运行时。

运行时不能绑死在某一种远程协议上。

不同的MCP服务器可能有不同的任务接口。

所以要把协议适配抽出来。

抽出来的东西就是驱动。

驱动回答"怎么和一种远程任务接口通信"。

运行时回答"任务的生命周期怎么管理"。

两者分离。

这个模块定义驱动的协议。

协议有三个方法。

提交任务。

查状态。

取消任务。

这个模块还定义驱动注册表。

注册表是进程内的。

Gateway启动时装配。

## 二、模块里的主要成员

- McpTaskDriver：驱动协议。定义submit、get_status、cancel三个方法。
- submit(request)：提交任务。返回提交结果。
- get_status(task)：查任务状态。返回任务快照。
- cancel(task)：取消任务。返回任务快照。
- McpTaskDriverRegistry：进程内的驱动注册表。
- register(name, driver)：注册驱动。空名字报错。重名报错。
- get(name)：按名字取驱动。没有返回None。
- names()：返回所有已注册驱动名的排序元组。

## 三、它和谁协作

- 它依赖mcp/tasks/models的数据结构。
- 它被mcp/tasks/runtime消费。运行时从注册表取驱动。
- mcp/tasks/ordinary.py实现这个协议。普通MCP工具契约是一个驱动。

## 四、重要性评级

评级是4分。

理由是它是任务运行时的协议层。

协议分离让运行时不绑死某一种远程接口。

注册表让Gateway启动时装配驱动。

但它只是协议和注册表，没有业务逻辑。

体量很小。
