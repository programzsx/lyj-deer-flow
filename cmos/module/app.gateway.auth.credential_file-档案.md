# app.gateway.auth.credential_file 档案

## 一、这个模块是干什么的

这个模块负责把初始管理员凭据写到一个受限制的文件里。

管理员首次启动或者重置密码时。系统会生成一个初始密码。这个密码需要告诉运维人员。

直接把密码打到日志里是不安全的。日志会被ELK或Splunk等系统收集。密码就会扩散。

这个模块把密码写到一个权限为0600的文件里。只有进程用户能读这个文件。调用方在日志里只记录文件路径。运维人员去文件里拿密码。

## 二、模块里的主要成员

### 1、write_initial_credentials函数

这个函数是模块唯一的公开函数。

函数签名是write_initial_credentials(email, password, *, label="initial")。

函数的处理流程如下。

- 先算出目标文件路径。路径是base_dir下的admin_initial_credentials.txt。
- 创建父目录。
- 拼出文件内容。内容包括邮箱、密码、提示信息。提示信息告诉运维人员登录后要改密码，然后删掉这个文件。
- 用os.open创建文件。权限是0o600。标志是O_WRONLY加O_CREAT加O_TRUNC。
- 把内容写进文件。
- 返回文件的绝对路径。

### 2、两个设计细节

第一个细节是原子创建。文件用一次os.open调用创建。权限在创建时就生效。这样避免了先写文件再改权限的窗口期。在窗口期里密码可能被其他用户读到。

第二个细节是O_TRUNC而不是O_EXCL。重置密码时文件可能已经存在。用O_TRUNC可以直接覆盖旧内容。不需要先删再建的额外步骤。

### 3、label参数

label参数区分两种事件。

- initial：表示首次创建。
- reset：表示密码重置。

label写在文件头部。运维人员在重启后拿到文件，能知道这个文件是哪次事件产生的。

## 三、它和谁协作

### 1、它依赖谁

- deerflow.config.paths.get_paths：提供base_dir，定位凭据文件。

### 2、谁调用它

重置管理员密码的流程会调用这个函数。reset_admin模块负责重置逻辑。重置成功后调用write_initial_credentials落盘新密码。

## 四、重要性评级

评级是4分。

理由如下。

这个模块只做一件事。这件事是写一个凭据文件。代码量很小。逻辑也很简单。

但是这件事有安全价值。密码不能进日志。密码需要一个安全的交付通道。这个模块就是那个通道。

这个模块不是系统的核心链路。日常请求不会经过它。只有初始启动和密码重置会用到。所以评级是4分。
