# deerflow.config.verification_config-档案

## 一、这个模块是干什么的

这个模块管理子代理结果验证层的配置。

子代理把任务结果交还给主代理。

结果的质量需要验证。

这个配置管理三层验证机制。

第一层是收据账本。

第二层是验收清单。

第三层是选择性评审。

## 二、模块里的主要成员

### 1、VerificationConfig类

`receipts_enabled`决定是否在每个工具结果上盖确定性收据，默认开启。

`receipts_render_mode`选择收据账本的渲染模式。

两种模式。

`always`是总是渲染。

`delegation_only`是只在处理子代理结果时渲染。

主代理链用这个配置。

子代理链总是渲染，因为引用要在那里产出。

`judge_enabled`决定是否运行一次性的小模型评审，默认关闭。

评审对象是携带验收标准的已完成子代理结果。

`judge_model_name`是评审用的模型。

不设置时回退到父代理的模型。

## 三、它和谁协作

`app_config.py`的`verification`字段是这份配置。

收据验证中间件和评审运行时消费这份配置。

`tool_receipt.py`提供收据的具体实现。

## 四、重要性评级

评级：5分。

理由：结果验证是子代理体系的质量保障。收据的默认开启说明它是核心路径。评审是可选的第二道，默认关闭。配置面小但语义分层清晰。
