# deerflow.config.run_events_config-档案

## 一、这个模块是干什么的

这个模块管理运行事件存储的配置。

运行事件包括消息和执行轨迹。

这些数据要持久化下来。

这个配置决定存到哪种后端。

三种后端可选。

memory用于开发和测试，重启即丢。

db走SQL数据库，支持完整查询，适合生产。

jsonl是追加式的JSONL文件。

轻量替代方案，适合需要持久化但不想上数据库的单节点部署。

## 二、模块里的主要成员

### 1、RunEventsConfig类

`backend`选存储后端，默认memory。

`max_trace_content`是轨迹内容的最大字节数，超过就截断。

只对db后端生效。

`track_token_usage`决定运行日志是否累计令牌数到RunRow。

默认开启。

## 三、它和谁协作

`app_config.py`的`run_events`字段是这份配置。

这个字段是启动专用的。

事件存储工厂在启动时选定实现。

选定的实现被冻结到app.state上，和底层事件存储保持配对。

## 四、重要性评级

评级：5分。

理由：运行事件是排障和审计的数据基础。三种后端的选择覆盖开发到生产。但配置面只有三个字段。
