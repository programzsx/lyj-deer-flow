# deerflow.community.aio_sandbox.ownership.base

## 一、这个模块是干什么的

这个模块定义沙箱所有权存储的契约。

背景是这样的。

多实例部署时多个Gateway共享沙箱容器。

但每个实例有自己的内存暖池。

没有共享的所有权状态。

一个实例的启动对账会认走别的实例正在用的容器。

然后把它空闲销毁。

别的实例的工具调用就会失败。

这是一个真实缺陷，编号是4206。

解法是共享的所有权存储。

租约回答一个问题。

问题是"哪个实例负责销毁这个容器"。

不是"哪个实例可以用它"。

这个区分驱动了整个接口。

使用是不需要租约的。

同一个线程的连续回合可以落在不同实例上。

当前服务这个线程的实例直接从持有者那里拿走租约。

销毁是相反的。

认领只有在容器无主或已属于自己时才成功。

这样实例永远不可能认走活着的peer正在负责的容器。

租约有两个状态。

own:表示"我负责这个容器"。

del:表示"我正在销毁这个容器"。

接管会被del:租约拒绝。

这保证容器不会在销毁的认领和容器停止之间被重新拿走。

契约还有两条实现要求。

要求一是所有方法都是同步的。

因为所有权由提供者构造、后台线程和同步释放路径驱动。

要求二是后端失败要抛异常而不是返回假值。

所有权发布不出去的沙箱不能交出去。

所有权证明不了自由的容器不能销毁。

## 二、模块里的主要成员

- SandboxOwnershipStore：抽象基类。定义所有权租约的接口。
- owner_id：实例的唯一id。
- take(sandbox_id)：拿走租约。从持有者那里接管。
- claim(sandbox_id, for_destroy)：认领租约。销毁用的认领要求无主或已属于自己。
- renew(sandbox_id)：续租。返回RenewOutcome。
- release(sandbox_id)：释放租约。
- owner(sandbox_id)：查当前持有者。
- close()：关闭存储。
- OwnershipBackendError：后端无法回答时抛出的异常。
- RenewOutcome：续租的结果枚举。

## 三、它和谁协作

- 它被community/aio_sandbox/ownership/memory.py和redis.py实现。
- 它被community/aio_sandbox/ownership/factory.py按配置选择实现。
- 它被aio_sandbox_provider消费。提供者发布、认领、续租所有权。

## 四、重要性评级

评级是8分。

理由是它是多实例容器共享的正确性核心。

没有它，实例会互相认走并销毁正在使用的容器。

两个租约状态的设计保证销毁窗口安全。

同步和抛异常的契约要求防止调用方fail-open。

它是真实缺陷的解法。
