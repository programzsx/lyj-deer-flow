# deerflow_extension_api.runtime_bridge 档案

## 一、这个模块是干什么的

这个模块是LangGraph运行时上下文和任务级存储之间的"桥"。

背景是这样的。

中间件跑在agent图里。只能通过`request.runtime`够到宿主状态。

宿主把任务级存储装在一个宿主拥有的键下。

中间件通过这个桥读它。

核心规则是一句话。

扩展读桥。把自己的对象放进存储里。

扩展绝不直接写运行时上下文。

这样两个扩展不会在运行时上下文的键上撞车。

## 二、模块里的主要成员

- `EXTENSION_TASK_STORE_KEY`。常量。值为`__deerflow_extension_task_store`。宿主拥有的键。扩展不许直接写运行时上下文。

- `task_store_from_runtime(runtime)`。返回任务级存储。没有活跃任务时返回None。它检查context是Mapping。检查存储是ExtensionData实例。类型不对也返回None。

## 三、它和谁协作

它依赖同包的`state.py`拿ExtensionData。

宿主在运行时上下文里装任务存储。

扩展的中间件通过这个桥读。

扩展自己的状态放在ExtensionData里。键是类型。不是字符串。

## 四、重要性评级

评级是2分。

理由如下。

它只有25行。一个常量加一个函数。

但它是扩展中间件拿宿主状态的唯一合法通道。桥虽小。边界价值真实。

它防止两个扩展在运行时上下文键上撞车。这个约束靠它落实。

扣分原因。体量极小。功能单一。任何中等水平的开发者看一眼就懂。它是整批模块里最小的之一。
